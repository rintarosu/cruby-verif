# cruby-verif

[![Docker CI](https://github.com/rintarosu/cruby-verif/actions/workflows/docker-action.yml/badge.svg?branch=master)](https://github.com/rintarosu/cruby-verif/actions/workflows/docker-action.yml)

Formal verification of C functions extracted from [CRuby](https://github.com/ruby/ruby)
using the [Verified Software Toolchain (VST)](https://vst.cs.princeton.edu) and the
[Rocq Prover](https://rocq-prover.org).

Based on [rocq-community/rocq-program-verification-template](https://github.com/rocq-community/rocq-program-verification-template).

## Targets

| CRuby source | Function | C file | Status |
|---|---|---|---|
| `util.c` | `ruby_scan_digits` | [`src/util/scan_digits.c`](src/util/scan_digits.c) | in progress |

Each extracted C file starts with a comment that lists every change made to
the original CRuby code.

Reference CRuby revision: `ruby/ruby@3e6368577177b3c3e2119fec09fb0f69edccabee`

## Layout

```
src/<cruby-file>/<name>.c                 C code extracted from CRuby
theories/<cruby-file>/<name>.v            Clight generated by clightgen
theories/<cruby-file>/<name>_theory.v     Mathematical definitions and lemmas
theories/<cruby-file>/<name>_verif.v      VST specification and proof
```

The Rocq logical path is `CRubyVerif`, e.g. `CRubyVerif.util.scan_digits_verif`.

## Building

### With Docker (recommended)

```shell
docker build -t cruby-verif .
docker run --rm -it -v "$PWD":/work cruby-verif make -j4
```

For an interactive shell inside the container:

```shell
docker run --rm -it -v "$PWD":/work cruby-verif
```

### With a local opam installation

```shell
opam repo add rocq-released https://rocq-prover.org/opam/released
opam install --deps-only ./cruby-verif.opam
make -j4        # or: dune build
```

## Generated Clight files

The `theories/**/<name>.v` files generated by `clightgen` are kept in version
control, because the target architecture affects the output (for example,
`char` is unsigned on aarch64 and signed on x86_64) and CI must build the same
files as local development. The committed files were generated on **aarch64**.

To regenerate one:

```shell
make clight   # inside the Docker container
```

## Adding a new function

1. Copy the function into `src/<cruby-file>/<name>.c` and record the changes
   from the original in the header comment.
2. Run `clightgen` to produce `theories/<cruby-file>/<name>.v`.
3. Add `<name>_theory.v` and `<name>_verif.v`.
4. List the new `.v` files in `_CoqProject`, and add a `clightgen` rule to
   `theories/<cruby-file>/dune` and `Makefile.rocq.local`.
